## Implemented boundary

- Added a fixture-only Repair Recovery Controller bound to one immutable RunRecord.
- Repair attempts must match run ID, selected Day, Git fingerprint, allowed paths,
  active-work limit, and the two-attempt limit.
- Guard rejection does not consume an attempt or change state.
- A verified bounded result enters `REVALIDATING` only.
- The second occurrence of the same failure fingerprint enters
  `HUMAN_ACTION_REQUIRED`; a third attempt is rejected.
- Only a review matching request ID, run ID, Day and failure fingerprint can return
  the same RunRecord to `PREFLIGHT`. Attempt history is not reset.

The controller records decisions only. It does not edit a file, perform a repair,
start a Day, send a review, or grant new authority.
